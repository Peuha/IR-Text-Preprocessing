# پیش‌پردازش متن برای بازیابی اطلاعات

پروژه‌ی درس «مبانی بازیابی اطلاعات و جستجوی وب
رامتین جوزی روز یکشنبه ۱۵:۴۵

برنامه یک متن خام انگلیسی را به فهرستی از اصطلاحات (Terms) پردازش‌شده تبدیل می‌کند و خروجی را با یک «خروجی طلایی» دستی مقایسه و Precision و Recall را محاسبه می‌کند.

## مراحل پایپ‌لاین

1. **دریافت متن** (از فایل با `--file` یا از خط فرمان با `--text`؛ بدون آرگومان، سه متن آزمایشی سند)
2. **توکن‌سازی**: حذف علائم نگارشی، حفظ کلمات خط‌فاصله‌دار (`state-of-the-art`)، حذف پسوند مالکیت (`John's` → `John`)، شناسایی مخفف‌ها (`U.S.A.` → `USA`)
3. **یکسان‌سازی**: تبدیل به حروف کوچک (`U.S.A.` و `USA` هر دو `usa`)
4. **حذف کلمات ایست**: فهرست ثابت داخل کد (شبیه فهرست انگلیسی NLTK)
5. **ریشه‌یابی**: پیاده‌سازی دستی الگوریتم Porter

حذف کلمات ایست عمداً **قبل** از ریشه‌یابی انجام می‌شود. خروجی هر متن ترتیب ظاهر شدن را حفظ می‌کند و **تکرارها حذف نمی‌شوند** (مثل توالی توکن‌ها در نمایه‌سازی). فقط در ارزیابی، اصطلاحات به‌صورت مجموعه‌ی متمایز مقایسه می‌شوند.

## اجرا

نیازمندی: Python 3 (بدون هیچ کتابخانه‌ی خارجی)

```bash
python3 Firstname_Lastname.py
```

این دستور سه متن آزمایشی را پردازش می‌کند، Precision و Recall هر کدام را چاپ می‌کند و خروجی را در `outputs.json` ذخیره می‌کند.

دریافت متن از بیرون (مرحله‌ی ۱ سند): از فایل یا از خط فرمان

```bash
python3 Firstname_Lastname.py --file input.txt
python3 Firstname_Lastname.py --text "Friends, Romans, countrymen"
```

نسخه‌ی گرافیکی (یک صفحه‌ی محلی در مرورگر که در آن متن را تایپ می‌کنی):

```bash
python3 Firstname_Lastname.py --gui
```

بدون هیچ آرگومانی، سه متن آزمایشی سند (که داخل کد قرار دارند) پردازش و ارزیابی می‌شوند.

## ارزیابی

- خروجی طلایی (`GOLD` در کد) **دستی** و فقط بر اساس قواعد سند ساخته شده، نه با اجرای برنامه.
- معیارها روی مجموعه‌ی اصطلاحات متمایز محاسبه می‌شوند:
  - Precision = |O ∩ G| / |O|
  - Recall = |O ∩ G| / |G|
- مخرج صفر ⇒ مقدار معیار صفر.
- اصطلاحات اضافه (O − G) و جاافتاده (G − O) برای تحلیل خطا چاپ می‌شوند.

## نتایج

| متن | Precision | Recall |
|-----|-----------|--------|
| ۱ | 1.00 | 1.00 |
| ۲ | 1.00 | 1.00 |
| ۳ | 1.00 | 1.00 |

## تصمیم‌های طراحی

- **فهرست ایست:** ثابت و داخل کد، تا نیازی به `nltk.download` نباشد.
- **ریشه‌یاب:** Porter، پیاده‌سازی شخصی بدون کتابخانه.
- **کلمات خط‌فاصله‌دار:** یک توکن می‌مانند و ریشه‌یاب روی کل توکن اعمال می‌شود.
- **مخفف‌ها:** الگوی حروف جداشده با نقطه (`U.S.A.` یا `U.S.A`)؛ نقطه‌ها حذف می‌شوند.
- ریشه‌ها لزوماً کلمه‌ی معنادار نیستند (مثلاً `device → devic`، `quality → qualiti`).

## افزوده‌ها (فراتر از سند)

- **حالت `--gui`:** یک صفحه‌ی محلی (فقط با کتابخانه‌ی استاندارد پایتون) برای تایپ متن و دیدن خروجی هر مرحله، و دکمه‌ای برای اجرای سه نمونه با Precision/Recall.
- **حالت `--trace`:** خروجی هر مرحله (توکن‌ها ← حروف کوچک ← بدون ایست ← ریشه‌یابی) را چاپ می‌کند تا بشود خطا را به یک مرحله نسبت داد. همچنین تعداد اصطلاحات متمایز قبل و بعد از ریشه‌یابی را نشان می‌دهد.
- **دو تست مرزی با خروجی طلایی دستی** (`edge1`, `edge2`): مخفف همراه با پسوند مالکیت (`C.E.O.'s`)، تاریخ خط‌فاصله‌دار، `e-mail`، حذف دوحرف‌یکسان (`running → run`)، و حالت‌هایی که ریشه‌یاب عمداً تغییر نمی‌دهد (`runners → runner`، `bones → bone`).

```bash
python3 Firstname_Lastname.py --trace
```
